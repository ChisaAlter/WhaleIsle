# Project 产品重设计：长期对话与持续工作

版本：3.1 · 2026-10-08。状态：设计稿，待实现与真实验收。

本文替代 [2.0 设计](2026-10-07-local-project-agent-teams.md) 中的目标产品设计。当前实现状态仍见 [功能资料](../../features/projects.md)；文中的目标行为不能作为已实现或已验证的证据。执行基础以 [Project × Agent Teams 实现架构](2026-10-08-project-team-architecture.md) 为准，后台工作必须使用真实 Team。配套模型行为见 [提示词与交接契约](2026-10-08-project-prompts.md)。

## 1. 产品承诺与设计依据

用户选择一个本地目录，在一条长期主对话里提出需求、查看结果并继续同一件工作。Project 负责记住工作背景、安排实际执行、汇总成果；用户无需管理 worker、任务编号或内部存储。

设计依据按优先级排列：

1. 用户确认的本地目录与本地执行；创建只选目录，真正工作从对话开始。
2. 最新要求：Project 分类位于工作区下面；工作进度复用普通任务的浮动折叠条；整体设计达到完整业务模块，而非逐处修补按钮。
3. 用户提供的 `harness-project.md` 与 `harness-project-prompts.md`：唯一协调者、后台持续 worker、增量续接、结构化交接、用户成果与内部笔记分离。
4. 仓库设计语言、普通对话、文件预览和任务保护的既有交互。

原文的远端仓库前提、默认云端执行、独立 Project 导航页、删除物化目录流程不适用于本版。原文的 JSON 收尾语义由当前 `project_report` 与真实运行结算承载。Project 必须与鲸屿 Agent Teams 结合：协调者就是 Team Lead，worker 是真实 teammate，工作关联原生 Team task，协作与续接使用原生 mailbox。原文中不使用 Team runtime 的方案不再采用。

完成标准是用户能走通“提出工作 → 看到真实进展 → 获得可打开的成果 → 追加并继续 → 停止及恢复”，包括失败与重启；创建入口和静态面板可用不足以交付。

## 2. 概念与职责

沿用现有名称，不新增任务平台实体。

| 概念 | 产品含义 | 用户接触方式 |
| --- | --- | --- |
| Workspace | 已登记的本地目录及其文件访问能力 | 普通工作区、目录选择和文件浏览 |
| Project | 绑定一个目录，保留一条主对话、持续工作与资料 | 侧栏项目条目、主对话、项目资料 |
| Workstream（界面称“工作”） | 可以反复追加要求的一件事 | 有意义的标题、状态、成果和对话中的指代 |
| Worker | 承接某件工作的后台执行会话 | 必要时查看只读过程，日常无需管理 |
| 一轮结果 | 对一次已接受要求的报告、验证与成果引用 | 主对话中的结果说明及历史成果 |

同一规范目录在一个 profile 中只有一个 Project；普通会话可同时使用该目录，互不迁移。Project 的排队只协调自身 worker，不锁住用户或其他应用。

“已完成”描述当前要求已经完成且必要验证通过；“运行已结束”不等于完成。“需要处理”描述一个具体阻碍，必须说明原因和可行下一步。

## 3. 界面结构

```text
侧栏                         主区域
工作区                       项目名称 · 工作目录 · …      项目资料
  原有普通工作区             原有对话 / 轨迹
Project                  +   用户：查一下登录错误
  商城服务    进行中          助手：已开始调查登录错误……
  文档站      需要处理        助手：原因是…… [调查报告]
  工具库                     ……
                             [登录错误 · 正在验证；另 1 项排队  ˄]
                             [原有输入框：追加要求、继续工作……]
```

这是信息结构示意，不是新的皮肤或已验收截图。控件、菜单、字体、间距、材质、动效遵循 `docs/design-language.md`；复用普通会话的行、菜单、TaskDock、输入框和预览。

### 3.1 侧栏和搜索

- 没有“会话 / Project”顶部切换。Project 是工作区下面的同级分类，使用同一滚动区域；多个 Project 是分类下的条目。
- 可用且没有项目时也保留紧凑分类与添加入口；不占用大块空白说明。分类标题可折叠，`+` 复用目录选择器，分类菜单提供“查看已归档项目”。
- 一条项目行显示名称和必要状态，长名称省略且可悬停查看完整名称/目录。默认不重复铺长路径；同名项目用短目录辅助区分。
- 不因创建 Project 自动多出同目录空工作区组。既有工作区、用户主动登记的空工作区及普通会话保持可见；只隐藏明确由 Project 创建且没有普通用途的空组。来源不明的已有登记保留，不能凭“为空”删除或隐藏。
- 搜索框同时搜索普通会话和项目名，结果按现有类型区分；Project 命中始终打开唯一主对话。worker 和内部笔记不进入结果。默认不含已归档项目；查看归档后可在归档范围搜索。
- 复用现有选中、键盘导航和菜单交互。右键、行尾更多按钮、键盘菜单键到达同一菜单：重命名、打开工作目录、归档；归档项目提供恢复。重命名同步项目行、主对话标题和资料标题，不改目录。
- 顺序随用户实际对话/工作活动更新，不因读取、轮询或展开进度变化；沿用现有排序习惯。

### 3.2 主对话

主区域直接使用普通聊天。项目名与绑定目录保持单行，长路径省略；项目资料为一个附属入口。没有任务创建表单、第二输入框、成员管理页或必经总览。

首次打开的空状态只需一句：“在这里提出需求，后续可继续同一项工作。”名称和目录已由顶栏表达，不在进度里重复说明。创建不发模型消息、不生成欢迎任务。

用户消息的状态必须真实：协调者接受请求、worker 排队、开始执行、收到追加、结束，是不同事实。仅写入索引不能回复“已经开始”；追加进入队列不能说“已经按新要求修改”。

普通问题、解释已有结果直接回答。实际执行由后台承担；协调者可在执行期间继续响应用户。进度更新留在进度条，关键结果、阻碍、需要选择的事项回到主对话；不把每个工具调用刷成聊天消息。

### 3.3 工作进度

- 使用普通任务相同的 TaskDock，悬浮在输入框上方，默认折叠成一行，点击展开。首次创建且没有工作/异常时不显示空进度面板。
- 折叠行说明“当前工作 + 状态”，例如“登录调查 · 进行中”“需要你确认部署范围”“正在停止后台工作”“2 项进行中 · 1 项排队”。完成数量只能作辅助。
- 展开后优先列需要处理和活动中的工作，再列本次对话相关的最近结果；更早完成项进入历史，按需读取。每行只放标题、当前状态、必要说明和相关操作。
- 查看某项才显示执行目录/分支、报告、验证和只读过程。长报告不直接堆入整个输入区；资料与过程在已有附属表面打开。
- 进行中可停止该项；阻碍显示具体原因与处理入口；完成结果可打开成果。归档、恢复项目、重命名、全局偏好不出现在进度条。
- 展开高度受当前会话可用空间限制，列表内部滚动；窄窗口仍保持输入框、发送/停止入口可用。展开状态属于本地浏览状态，切换项目默认折叠，不随每次状态刷新重置。
- 停止未完成时持续显示“正在停止”，不能先显示停止成功。异常不会因为折叠、切换项目或 worker 不再输出而消失。

### 3.4 项目资料

入口打开现有附属表面，包含“成果、笔记、偏好”三个明确页签，默认成果。

- 成果按所属工作和更新时间列出可打开的文件、当前结果和历史版本。显示文件名、简短说明、所在位置类型（项目资料/工作目录/独立分支）；完整路径按需查看。
- 笔记首先展示可编辑的用户笔记；自动工作摘要作为只读附属内容，不让英文机器日志、内部 ID 和长路径占据主内容。
- 偏好是该项目的长期要求，说明其只作用于本项目、最新明确要求优先。保存反馈与错误复用现有文件编辑体验；保存、取消、脏内容离开保护一致。
- 文件打开直接经受信绝对路径交给既有预览。PDF、Office、图片或大文件不以“先按 UTF-8 读成功”为前提；原有预览不支持的格式显示原因及现有可用打开方式。
- 资料故障定位到具体项目/文件，保留其他可用入口。不存在的成果显示缺失及原路径，不打开同名替代文件。

## 4. 从创建到持续工作的完整流程

| 场景 | 用户操作 | 产品响应与结束条件 |
| --- | --- | --- |
| 新建 | 新对话目录菜单“添加 Project…”或分类 `+`，选本地目录 | 规范化目录、绑定唯一项目，进入主对话；非 Git 有效；不自动执行 |
| 取消/重复选择 | 取消选择；选择已有项目目录 | 取消无新记录并保留草稿；重复打开原主对话；归档记录显示恢复入口，不造第二份 |
| 问已知事实 | “刚才为什么这样改？” | 从现有结果直接回答，不创建 worker、不重复调查 |
| 首次工作 | “调查登录错误，只读” | 建立工作并开始只读执行；说明已开始或真实排队原因；不能改代码或运行写入命令 |
| 工作中追加 | “同时考虑空密码” | 关联原工作，交到原 worker 的执行边界；显示追加已接受或等待接收；无同类新 worker |
| 完成后续接 | “把报告复现步骤写细一点” | 继续原 worker、原目录和上下文；保留旧成果，形成新一轮结果；正确部分不重做 |
| 独立工作 | “再检查支付模块” | 单独建立有清楚标题的工作；只读可并行，共享可写目录排队 |
| 明确并行开发 | “前后端并行改” | 先核对目录/基线/依赖；需要时说明独立 worktree 与整合安排；不能暗中丢开用户脏树 |
| 需要用户输入 | 缺少确实影响执行的决定 | 主对话说明具体问题，相关工作标“需要你确认”；其他独立工作继续；一次回答回到原工作 |
| 结束 | worker 提交结果且运行结算 | 协调者说明结果、验证和剩余事项，附可打开成果；失败或必要验证未通过不能写完成 |

相关模型配置复用普通会话。缺凭据等已知问题在原有模型设置路径解释并提供入口，不创建虚假的运行工作。创建项目仍可成功，不要求为了保存目录先配置模型。新 worker 使用协调者当前模型选择；已存在 worker 保留原会话模型，切换主对话模型不暗中切换正在运行的工作。

## 5. 停止、继续、归档与重启

删除独立“暂停 / 解除暂停”产品操作，统一为停止和通过明确要求继续。已有暂停数据继续表达为“已停止/等待继续”，迁移不自动开工。

| 操作 | 范围 | 用户看见的结果 |
| --- | --- | --- |
| 主对话停止 | 协调者当前执行、此项目活动与排队工作 | 先“正在停止”，实际排空后“已停止”；保留消息、资料与已有成果 |
| 停止某项 | 指定工作及其拥有的执行活动 | 只停止该项；其他独立工作不受影响；被撤下的排队要求不会暗中重启 |
| “继续登录那项” | 可明确定位的原工作 | 新的真实用户要求续接；无需先点击解除暂停；含糊且影响范围时才澄清 |
| 点击“继续这项工作” | 原工作的一次明确续接 | 通过普通发送链记录可见的用户请求并定位原工作；不走绕过授权的后台 RPC；不覆盖已有输入草稿 |
| 空闲时归档 | 项目及其导航记录 | 从活动分类隐藏，当前对话保留可读归档态；目录、历史、资料保留 |
| 有活动时归档 | 整个项目 | 复用既有活动确认：“停止后台工作并归档”；真实排空后归档；失败留在原项目并解释 |
| 恢复项目 | 归档关联 | 返回同一主对话；不会自动恢复旧任务；由新的用户要求继续 |
| 应用重启 | 恢复记录与真实状态 | 已完成结果保留；受中断工作显示“上次工作已中断，可继续”；无工作项目仍为空闲 |

当协调者已空闲但 worker 仍运行时，输入区的停止入口仍须反映项目后台活动；不依赖协调者是否正在输出决定可否停止。已归档对话用明确恢复提示代替可发送输入，避免消息进入后被后台拒绝。

归档确认后立即进入“正在归档”的准入状态，主对话暂为只读，阻止新消息、委派和继续与归档并发。实际排空且归档状态持久化成功后才报告归档完成。失败保留未归档记录、具体原因和停止保持；真实停止完成前不能重新开工，之后仍须新的用户要求才继续。

停止意图先在运行中的准入判断生效，并立即取消实际活动。持久化失败必须报告，但不能阻挡取消；失败状态保持禁止自动推进。重启仍不自动恢复活动，避免未写下的停止意图被绕过。

## 6. 状态表达与失败处理

使用 Team task/roster 与 Project 当前执行记录的业务事实，派生一个用户能理解的展示状态。展示优先级不能覆盖事实；一项阻塞时仍显示其他运行项数量。

| 优先级 | 条件 | 默认表达 |
| --- | --- | --- |
| 1 | 正在排空执行活动 | 正在停止；展开可见仍待结束的项 |
| 2 | 权限/环境/输入/执行失败阻碍了当前要求 | 需要处理 + 具体原因；其他运行项数量保留 |
| 3 | 正在创建、执行或验证 | 当前工作 + 进行中；有可靠阶段才写“正在验证” |
| 4 | 等待同目录写入位置 | 排队中；说明等待哪项释放目录 |
| 5 | worker 已结算，结果尚未回到主对话 | 正在汇总；汇总失败改为“结果已保存，汇总失败” |
| 6 | 用户停止/应用中断后等待新要求 | 已停止/上次工作已中断 |
| 7 | 当前要求均完成或尚无工作 | 已完成/空闲；无工作不显示空进度条 |

侧栏使用同一聚合规则，只显示需要关注的短状态。项目状态是后台投影，不依赖用户打开该项目才能刷新；轻量列表带聚合事实，详情按需读取，避免轮询每个项目全部报告。

错误必须给出“什么没有完成、已有内容是否保留、下一步是什么”。缺凭据连接既有模型设置；目录缺失展示原目录并保留历史，用户找回原目录后重新检查；worker 会话缺失保留原记录，明确不能续接，用户可要求新工作，不能伪造成功恢复。

插件不可用时保留紧凑的不可用说明和现有设置/诊断入口。一个项目的资料错误不使其他项目消失。禁止无依据自动重试、自动换模型/目录/权限；同样不为已经授权的正常续接反复要求确认。

## 7. 成果与完成定义

一次交接包含：本轮要求标识、结果（完成/受阻/失败）、简短结论、实际成果、实际验证、剩余事项。实际原生运行结算与本轮报告共同确定状态，旧报告不能覆盖新要求。

- “完成”要求约定工作完成且必要验证通过。只读调查可说明证据来源；确实无需测试时说明原因，不能捏造测试。因环境无法做必要验证则保留产物，状态为需要处理。
- 协调者给用户的回复包含做了什么、关键结果、可打开成果、验证与未完成事项；只展开用户需要的信息。后台报告不等于独立审查结论。
- 当前目录差异明确叫“当前目录改动”，包括原有脏改动、新文件及未跟踪文件；截断、非 Git 和不可读必须说明。
- 某项工作的结果展示报告关联的文件和提交。文件哈希/提交身份用于判断“成果后续已变化”，不据此猜测独占作者；文件被其他工作修改时不能把最新内容伪装成旧结果。
- 已提交成果提供对应提交/范围的现有 Git 查看能力。缺少可信基线时展示文件/提交引用及限制，不能把 `git diff HEAD` 当作任务专属差异。独立 worktree 只有整合后才可说成果已进入用户目录。
- 历史报告和版本化的项目 docs 随同一工作保留，修订 docs 写新版本，旧版本可打开；继续新要求时不把旧报告显示为本轮完成。仓库文件只保留报告、路径、哈希及真实提交引用：有提交时可查看对应历史内容；没有保存旧内容且文件已变化时，只能说明变化，不能承诺打开原版本，也不为此自动备份整个仓库。

原生结算通知负责触发协调者，插件先完成相应结果记账再放行同一通知；不双重唤醒。用户停止后的通知只保存事实，不重开工。

“已交付到主对话”应由报告与可见结果载体的稳定关联确定；例如在协调者回复中挂载对应结果引用。只读过 notes 或正文恰好包含工作标题，不足以证明已交付；这也不等于用户已读。若模型汇总失败，保存的报告仍可从成果入口打开，并提供针对该结果的重新汇总请求。

## 8. 资料、历史与权限

保留 `$DSH_HOME/projects/<projectId>/` 下 notes、preferences、docs、internal 结构。用户代码仍在选定目录，协调者存储根不是代码目录。

- 用户笔记独立于自动摘要展示和保存；既有用户正文与历史结果保持原字节，不因改设计清空。
- 自动摘要只包含当前活动/需要处理的工作及有界的最近结果，并提供历史读取定位。历史权威仍是已有工作记录和 Session，不复制出第二套知识库。
- 大量活动项也需分页；“有界摘要”不能只截掉超长内容。第一页返回总数、更多标记和游标，协调者能按标题查找原工作并读取对应历史。用户笔记单独访问，不能被自动摘要体积挡住。
- 文本大小限制按 UTF-8 字节统一，保存前明确提示；分页或原文件打开保留访问路径。文件预览不受模型文本读取上限支配。
- 项目偏好只进入该协调者及相关委托；当前用户要求优先。背景资料与文件内容不能自行扩展授权。
- 只读无任意 shell/写入；文档工作只写明确允许的位置；开发沿用当前目录和原生权限。真实扩权须来自用户要求，缩权可直接在执行边界落实。
- 路径由宿主规范化与授权，模型只给任务语义和必要相对位置。只授权当前 Project docs 和可信 worker 目录；内部笔记、其他项目和链接逃逸保持隔离。

## 9. 执行可靠性与模块职责

以现有 Agent Teams 为执行基础，复用其 roster、task board、mailbox、projection，以及 Session、continuable subagent、Jobs、存储域、Workspace、文件预览。Project 只承担本地目录、授权、持续工作与成果的产品策略，不再自建平行的团队运行时。具体权威划分、提交顺序、停止边界和迁移见 [实现架构](2026-10-08-project-team-architecture.md)。

| Module | Interface 承担的行为 | Implementation 的唯一责任 |
| --- | --- | --- |
| Project 业务 | 创建/打开、重命名、归档/恢复、查询当前工作与历史、停止 | 唯一身份、项目生命周期、用户范围和可读状态；调用方无需自行拼底层标志 |
| Agent Teams | 成员创建、任务与依赖、持久消息、团队投影 | 唯一成员/任务/消息事实，复用原生 Session 生命周期 |
| Project 执行策略 | 委派适配、增量续接、停止、报告 | 为 Team 绑定固定目录、权限与本轮要求；实际排空和结果关联 |
| 资料与成果 | 查询、保存笔记/偏好、读取摘要/历史、打开结果 | 大小/格式/权限、真实文件身份、历史访问 |
| 客户端展示 | 普通导航、主对话、TaskDock、资料表面 | 呈现上述事实及反馈，不另外推导进程状态或调度任务 |

这是职责划分，不要求为了表格拆出四个框架。当前 `service.js` 要撤下重复的任务/成员权威，保留调用 Team 的业务适配；实际缺口才扩展 Team 的受信宿主接口。

目录占用释放后的队列推进必须覆盖正常结束、启动前失败和单项停止；不能依赖恰好出现无关事件。运行准入、取消和恢复遵守同一真实工作身份。一个项目的派生笔记失败记录到该项目，不让全局功能不可用。

同一工作串行接收新增要求；权限扩大只对已消费的新要求生效，旧活动不能提前得到新权限。终止原因、报告、本轮要求和实际运行身份关联；迟到旧结算仅更新自己的历史。

用户目录永不被自动 reset、stash、checkout 或删除。工作树清理仅处理明确由应用创建、真实归属可验证且无未提交/忽略文件的目录；分支和历史保留。重启先读事实，不启动模型。

### 可选 PR / CI 反馈

保留原设计的外部反馈方向，作为本地核心流程完成后的可选后续能力，本轮不实施。只在用户明确开启后观察其指定的仓库、PR 和 head SHA；非 Git/无远端项目照常使用核心功能。

PR 或检查变化回到原主对话，携带准确来源和与当前工作的关联。查询打开的 PR 消失不能推断合并，没有检查数据不能声称 CI 通过；查询失败保留最后观察并说明不可用。事件按真实交付/检查身份与状态变化去重并跨重启保存，不能用永久 branch+state 集合吞掉后续再次发生的变化。复用已有 Git/验证后的 webhook 能力，不新建根 Session、不把用户提醒当游标、不自动创建公网入口。信号只更新相关结果，在既有授权内处理后续；不能使用户已停止的工作自动重启。

## 10. 提示词交付

[配套文件](2026-10-08-project-prompts.md) 分为协调者、worker、首次委托、增量续接、结果交接五段。区分模型行为约束与必须由宿主保证的事实：

- 提示词承担选择直接回答还是委派、辨认跟进、保持范围、适度验证、简洁收口。
- 宿主承担路径、身份、权限、队列、取消、状态与结果关联。提示词写“不要重复工作”不能替代稳定 Session；提示词写“停止”不能替代真实取消。

## 11. 实施顺序与验收

按完整用户流程分阶段交付，每阶段先实现，再准备相应的最小验证。下列均为待执行，不继承旧检查为通过。

先以架构文档中的原生 Team 纵向链路为第一实现批次，验证成员、task、报告和原成员续接确实相连；不能先完成界面就宣布团队接入。以下用户路径是最终覆盖范围：

1. **导航与主对话**：统一分类、搜索、命名、菜单和唯一身份；原入口创建/取消/重复选择/归档恢复，保留普通工作区及草稿。已知不可用状态可解释。
2. **一次真实团队工作与成果返回**：主对话与 Team Lead、工作与 Team task、worker 与 roster 成员身份一致；接入完整提示词、正确的阶段状态与结果表达；真实模型在非 Git 目录完成指定只读/文档工作，成果可打开，主对话明确验证边界。
3. **追加、停止与故障恢复**：同一 worker 运行中/结束后续接，停止真实排空；同目录启动失败后后项推进；存储写失败不阻断取消；单项目笔记故障不影响其他项目；重启不开工。
4. **长期资料与多工作**：有界摘要、历史定位、长中文笔记、不同文件类型预览；多项状态可辨识，结果按本轮要求关联，共享目录差异不误归属。
5. **明确并行与安装包**：独立工作树、实际整合、跨项目权限、普通会话回归及目标安装包原入口全流程。

UI 观察覆盖：正常和支持的窄窗口、侧栏展开/收起、长名称、空/运行/排队/受阻/停止/已完成/归档、资料打开与返回。只检查受本次实现影响的场景；完整画面需人工评判层级、可读性、裁切和输入区空间。原型、DOM、构建和脚本模型不证明真实产品通过。
