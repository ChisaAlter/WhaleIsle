# 新建会话、历史与设置延迟实测（2026-10-27）

议题 [#271](https://github.com/ChisaAlter/WhaleIsle/issues/271)。在独立 profile 使用真实历史副本（初始 601 份约 1.17 GB，会话创建操作使数量略增）及约 2 MB 配置测试；原安装版与原用户数据保留。对照源码基线 `031fdff4d3` 和本次用量统计修复，使用同机官方 Electron 44.9.1，不以旧外壳代替原环境。

## 结果

| 操作 | 修改前就绪时间 | 修改后就绪时间 |
| --- | --- | --- |
| 新建会话，5 次 | 中位 3245 ms，194–15134 ms | 中位 146 ms，130–237 ms |
| 历史会话，5 次 | 中位 4692 ms，34–11504 ms | 中位 1086 ms，643–2192 ms |
| 打开设置，3 次 | 中位 62 ms，48–97 ms | 中位 35 ms，31–50 ms |
| 设置页切换，15 次 | 中位 37 ms，14–456 ms | 中位 28 ms，12–117 ms |
| 首次搜索，1 次 | 172 ms | 141 ms |

前后历史混合冷、暖样本，34 ms 的修改前样本属于已选中内容，不能当作冷历史性能。修改后首个大型历史仍有约 1.26 秒浏览器长任务，页面约 1.74 万 DOM 节点；该变化主要解决非统计操作被 Host 后台全语料扫描阻塞，不声称大型会话渲染已无长任务。

UI 操作为 CDP 输入事件，记录 `isTrusted`、可见及聚焦状态；新会话以可编辑输入区且无旧消息为就绪，历史以选中且聊天 flow 已出现、加载占位消失为就绪。性能测量未向模型发送消息。原始历史、截图、CPU profile 含私有内容，只在忽略的 scratch 保留，不提交。

## 定位与修复

Host 基线约 20 秒 CPU 采样中，日志复制 `structuredClone` 约 5.53 秒，存储行消费约 4.2 秒，另有解码、校验与 GC。用量插件原先启动和固定十分钟计时器都执行全语料扫描；设置搜索把所有页面隐藏挂载也会触发统计 RPC。

现仅统计数据请求触发精确扫描，并复用 `observeSession` 的投影、工作目录和标题，逐会话释放租约，避免完整 events 复制及额外回放。设置索引传 `indexOnly`，只挂可搜索标题与偏好行。首次、过期及强制刷新等待精确结果，排行等本轮完成后读取，不用 header 缓存宣称已确认日志末尾或健康。

隐藏搜索实机挂载 17 个 section，未发 overview 或排行请求。进入实际统计页能挂载正常统计 UI，无 slot error。最终追加真实冷统计完成：604/604 成功、failed/pending 都为 0，统计总量 712,718,735（当次 Magpie 128,234 次调用快照），topSessions 10 条；页面在超时后自动接收同次请求的结果，subtitle 恢复为「数据更新于 07:44 · UTC」，localStorage 保存时间为 07:54:32 UTC，刷新按钮恢复可用，项目排行挂载，页面共 20 条会话/项目排行行，无 slot error。以载荷 updatedAt 与保存时刻相减约 573 秒（9.6 分钟）；这是实际发现的显式统计冷读性能限制，不是即时刷新。

该冷扫描仍会解码、校验和折叠投影，prepared LRU 默认仅 5 个会话，并非永久预热。客户端 60 秒超时不能取消 Host 扫描；现对同次 RPC 成功设置回调，当前页面仍接收最终精确结果，并用请求 generation 排除卸载/新请求后的旧回写，不延长超时或添加轮询。该迟到路径的 10 项 API/lifecycle 定向测试（含原有 4 项）通过、客户端类型检查和构建通过。

## 验证

- 用量插件 205 项测试通过，Host/Client 严格类型检查及产物构建通过；覆盖不在启动读取历史、观察租约释放、重复刷新不翻倍、新用量及删除。
- 设置根组件与搜索 45 项通过。最初 forks worker 在启动阶段超时，未执行测试；改用 threads、两 worker 完成相同文件，未削弱断言。
- 桌面插件装配/链接/预设 19 项通过。
- 官方构建 9 项编译、Host/Client bundle、聚合类型与 Web 产物检查通过，重启独立源码实例后做上述实测。
- 主线 CI run [40453795951](https://github.com/ChisaAlter/WhaleIsle/actions/runs/40453795951) 第 2 次执行成功。原失败为 Windows pnpm-runtime 测试 worker 异常退出；同文件本地两项通过，无具体断言失败证据，未靠跳过或产品重试隐藏故障。

显式冷统计仍有大日志同步处理成本；正常安装版及用户正在使用的主 GUI未被本轮替换。诊断中一次默认 inspector 端口误连安装版并短暂暂停后立即恢复，此操作失误已记录，随后只在核实 PID 的独立 inspector 操作；未终止安装版或修改其数据。
