## User behavior

Project is a category below Workspace in the existing conversation sidebar. Selecting a local directory opens its unique continuing Lead conversation. Creation performs no model run, delegation, Git initialization or branch creation. Non-Git directories are supported. The ordinary conversation controls select the model and permissions; Project has no separate model setup or workbench.

Describe work in the main conversation. Accepted objectives retain every relevant real input and explicit requirement revisions. The original authorization ceiling owns investigation, repair and verification stages; a narrower worker stage does not require a repeated user authorization for the original goal. The Lead delegates to actual native Team members and tasks. Workers retain their original Session, preset, fixed cwd and owned worktree through explicit continuations. Read-only investigations may run concurrently. Development uses the selected directory unless independent Git worktrees are explicitly requested. Writers in identical or overlapping canonical directories are serialized, including across Projects; sibling directories and read-only work remain independent.

Progress uses the ordinary TaskDock, collapsed to one floating line above the composer. Its bounded detail shows current requirement goals and versions, pending delivery, applicable results, actual waiting reasons and failures, including objectives served without a worker. Older work and report versions are reachable through replacement pages. Whole-project status and archive confirmation use complete activity counts. Queued work can be withdrawn individually. Archive is a row context-menu action; archived Projects retain their conversation and materials. Notes and instructions cannot be edited until restoration; opening a recorded artifact still reads the current file at its original location.

Projects with the same name show the shortest distinguishing directory suffix below the title. Status shares that second line, preserving the title's width; the full original directory remains available on hover. The first entry provides one short instruction above the existing composer. Progress rows show the actual work state and relevant result, retry or stop action. Current execution and admission states take precedence over an earlier round's pending summary. Member records and current directory changes are available from the row's detail; original directory, branch and consumed execution permissions are disclosed separately. Directory changes may include pre-existing changes and other work, rather than a task's exclusive diff. Stop-in-progress is displayed before stopped, including at the individual work level.

Materials use Results, Notes and Project instructions tabs. Results present committed user deliveries with the original goal/version, conclusion, verification, remaining issues and files first. Supporting member reports remain available with independent pagination, visible summaries and expandable details. A result opened from progress targets that exact work, independent of the current results page. Earlier-report counts exclude the displayed latest report. The full saved-document inventory is separate and collapsed initially. Opening a historical delivery or report locates its real assignment input in the original Session; return retains the materials page, disclosures and unsaved notes. Team defaults to current members and recent work, with bounded historical task pages that retain original members.

Recorded artifacts show their filename, recorded size and original location type. Their file-actions menu reveals the original path. Opening a file uses its exact original work and report authority; materials, report history and document entries retain that same identity. Notes prioritize the editable user text and fold generated work records. Project instructions explain their scope. Switching tabs with unsaved text offers save, discard or continued editing; a failed save keeps the draft. Archived notes and instructions remain protected and explain restoration where it affects editing.

The native Team panel shows Project members and their actual activity. An inactive continuing member is labelled Idle. Task execution briefs expand on demand, retaining their complete original content; ordinary Teams retain their existing description previews. Member records fold assignments, peer messages and tool details. Assistant messages without visible text do not create empty headings; original records and pagination boundaries are preserved. New Project work titles and summaries describe objectives and deliverables, while execution restrictions stay in their supporting fields. Existing titles and reports are preserved.

A failed Lead summary keeps the saved results and presents a concise cause and recovery instruction. Missing credentials expose the existing native model settings; complete original diagnostics are available in a collapsed error disclosure. Settings and Project material/confirmation panels use the opaque elevated-panel token so underlying conversation text cannot show through their contents. The user's global glass preference is unchanged.

## Runtime contracts

- Each accepted human request has immutable delegation and native run identities. Worker reports, native completion, messages and cancellation are associated with those identities. Old completions cannot finish a new request.
- A Team task completes only after its current structured report, matching native completed settlement and owned Jobs agree. Native capacity and dependencies govern dispatch. Current prerequisite completion is checked and its exact references are frozen together before directory preparation. A prerequisite reopened during preparation returns the blocked admission to the queue.
- Reports preserve the prerequisite references actually supplied and consumed by the worker. New requests or replacement reports mark dependent results as changed; previous reports remain available, and completed downstream work does not automatically restart.
- Stop establishes an immediate source cutoff, cancels the Lead and workers and drains owned Jobs even when persistence fails. Directory occupancy remains held until actual drain. Restart and archive restoration start no model. Only a new user request permits stopped work to continue.
- Read-only and document scopes do not permit arbitrary repository writes or shell execution. Managed development commands can use native approval for one exact command and cwd. Reject, stop and late approval do not start that command or grant persistent permission. Ordinary Teams retain their existing permission behavior.
- A Delivery declares exact requirement/version, report and native run references. Its saved execution heads distinguish earlier phases of the same completed requirement from changes after declaration. Reused evidence already superseded when declared remains marked for review; later assignment, run and report changes also require review. It commits only after a genuine visible reply, completed turn and persistent Session flush confirmed true; notes reads and arbitrary progress replies leave results pending. Failed or duplicate declarations reconcile against their original durable events without restarting workers. A failed summary preserves the result and exposes the actual error. Summarize again sends an ordinary user message to the same Lead without replacing the composer draft or rerunning a worker.
- Detail returns at most 20 current summaries and three recent historical summaries. History, materials and report reads are paged; polling retains selected pages and rejects stale responses. Delivery and supporting report lists page independently, including when both exist. Historical delivery references preserve their original assignment/run/report identities and mark changed applicability for review.
- Generated notes prioritize blocked and active work and have a UTF-8 byte budget. The legal user-owned suffix is preserved completely; old oversized generated content remains readable within the same budget. Preferences apply only to this Project.
- Worktree cleanup checks original ownership and runtime drain, preserves dirty and ignored files and retains branches. User directories are never reset, stashed or removed. Windows long-path support is applied to Project Git commands without changing shared Git configuration.
