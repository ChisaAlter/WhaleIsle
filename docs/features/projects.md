# Feature: Local Projects

Project 保留完整普通对话，在右侧提供默认收起的悬浮任务栏。Super Agent 理解目标、排期、分发、协调、检查及交付；原生 Team/Subagent 成员执行实际工作。[设计](../superpowers/specs/2026-11-13-project-superagent-redesign.md) · [实施计划](../superpowers/plans/2026-11-13-project-superagent-redesign-plan.md) · [Issue #388](https://github.com/ChisaAlter/WhaleIsle/issues/388)。

## 入口与可用性

Settings › Interface › Project 默认开启；未保存过该设置的配置自动启用，已明确保存的关闭设置继续生效。切换开关会挂载或移除插件并重启 Harness，取消或拒绝重启会恢复开关。关闭保留磁盘数据，不改变普通会话的标准 Agent。源码可用 `WHALE_PROJECT=1` 强制开启。

新会话 Project 按钮使用当前目录，携带未发送的草稿与附件，不自动发送。工作区菜单提供新建或打开 Project。同一规范目录复用原主对话；磁盘根、主目录、受保护配置/数据目录及其祖先不能创建。主对话在普通侧栏目录下显示 Project 标签，目录按钮打开实际文件夹。

## 普通对话与任务卡

复用原生聊天、模型控件、附件、输入、停止、历史和文件预览，不另造聊天引擎。原生 Team 界面继续可用，不为 Project 隐藏或禁用。顶部 Tasks 打开 312px 右侧悬浮栏；宽聊天列预留空间，实际聊天列不足 920px 时覆盖显示，底部避开实测输入框。文件与原生右栏仍独立工作。

折叠不停止任务，并保留展开和阅读位置。正在看的卡完成后原位更新，用户显式重开或切组才重新归类。当前、已完成、已取消和归档列表使用真实分页。

一张卡代表一个完整目标。卡片显示实际成员工作、状态及等待原因；展开提供目标、约束、完成条件、版本、证据、文件与报告。成员入口打开原生持续对话，嵌套成员使用真实直接父会话；返回主对话只关闭当前成员页，空右栏收起，其他文件和成员页保留。保留单工作停止、目标取消/继续、完成卡归档/恢复、变更及安全还原。还原提交精确目标版本，依据已记录基线，拒绝活跃写入；冲突交由用户决定，不覆盖后续修改。资料保留项目规则、笔记、偏好、研究网站、文档和历史报告。汇总失败保留原成果，重试使用普通用户消息，不替换输入草稿。

## 原生执行与多目标调度

- Project 只为自己的主会话启用原生 Team，使用原生 spawn/fork、消息、后代与任务身份。普通会话默认值、实验 Team 用户配置不变。原生工具启动前的小型接点关联 Project 授权；其他会话仍走标准路径。
- 主 Agent 只有调度、协调和有界只读证据工具，没有命令、仓库修改或测试执行工具。成员继承有效用户要求、范围、文档路径、规范目录和原生审批。research 可读网络，不可写文件或跑命令。嵌套工作继承范围并归入同一目标；父成员需等待后代完成后报告。
- 多个已接受目标可同时活跃。只读和不同精确文档路径可并行；development/shell 预留重叠规范目录。显式依赖、实际资源及原生活跃成员容量只阻塞相关工作，不把整个目标串行化。旧 queued 记录可读，恢复后须显式继续。
- 原生 task ID 与 Project work ID 分开持久映射。结构化报告、对应成功结算和自有 Jobs 排空后才完成原生任务。原生 task board 上限计入已完成历史；停止或完成不会偷偷删除任务释放容量。它与 activation 容量不同。
- 依赖等待当前精确报告被验收；准备目录后、创建成员前重新核对依据。`project_review` 带检查证据接受或退回结果；持久化的 completed 最终交付也记录最终验收。partial 汇总和未提交草稿不放行依赖；已退回报告需明确重新验收。
- 要求版本、委派、运行、报告和交付保留来源身份。依据变化标明旧成果适用性，不改历史、不自动重跑。讨论、成员消息和运行时通知不是新执行授权。

## 停止、恢复与交付

输入框取消只停主 Agent 当前回合。单项停止排空该成员和登记后代，其他目标继续。停止后台工作取消主会话、成员及自有 Jobs，挂起所有未完成的已接受目标；继续只恢复选中目标。实际排空前仍保留目录占用。

冷恢复、恢复归档、读取详情和开启插件不自动执行旧任务。原主/成员会话、草稿、报告、资料、决策及授权继续保留；缺失或冲突授权明确报错，不能从摘要重建。用户可汇总已停止成果，不必恢复工作。

成员报告不等于目标完成。completed 要求当前完整目标、精确成功结果、检查证据且无未满足条件；partial 保留未完成项。交付必须成功声明、同回合可见最终回复、成功回合结束并通过原生持久化检查点才提交。失败保留原报告和恢复入口；既有有界临时模型服务汇总重试与执行调度分开。

### Steward redesign source changes (4.2)

The source implements P1–P4 of the [steward redesign](../superpowers/specs/2026-10-15-project-steward-redesign.md). The changes are committed on `main`; they are not installed, and full real-provider and visible desktop acceptance remains incomplete. The [manual acceptance checklist](projects-steward-acceptance.md) covers what remains.

- **Project rules**: `charter.md` (16 KB) is injected into every Lead step and worker brief. Rules override the model's own defaults; an explicit user exception is confirmed once and stated. Older Projects create the file lazily. The materials editor adds a Project rules tab with common-rule toggles and a size meter; the former instructions tab is labelled Preferences.
- **Board**: plain-language status badges with a reason and next step, a whole-Project overview strip, undo on discussed or queued cards, and direct requirement creation for clear goals.
- **Deliveries**: delivered cards list their files, open them with their recorded authority, and link to changes and result pages. The diff view is split by file with line counts and colouring.
- **Requirement changes**: after workspace preparation, the first write in each actual member directory records a baseline tree through a private temporary Git index; the user's index, refs and files are untouched. Multiple members in one directory share its baseline; explicitly isolated members retain their own directory and workspace receipt. Delivery captures every end tree in the queue transaction before releasing the next requirement. The diff identifies each directory, including same-named files in different workspaces. Repository-relative file paths and workspace directory labels are shown separately, including Projects bound below a repository root. Reverts use the same cross-Project parent/child-directory exclusion as development. All directories are checked before applying any reverse patch; a conflict in this preflight changes nothing. If a later file-operation failure interrupts a multi-directory revert, completed directories are recorded immediately and the error lists completed and remaining directories; retry touches only the remaining directories. Non-Git directories have no requirement baseline.
  A failed baseline is recorded against its directory without blocking ordinary work; the host reports that missing starting point instead of offering an incomplete automatic revert or taking a new baseline after writing. Older main-only snapshots remain usable. If an older record demonstrably omitted an executed isolated member's directory, its original data is retained and the coordinator must inspect that work before reverting it.
- **Decision log**: `project_deliver` accepts a `decision`; after a durable delivery the host appends it (or the summary's first line) to `decisions.md` once, and recent entries are injected into the Lead. Reverts are logged.
- **Queued preparation**: an authorized queued requirement may run read-only investigation; docs and development still wait for activation, and discussed or cancelled requirements cannot run. The Lead's open human turn is queried through `humanTurnOpen()`. No Agent Teams source change is required: system prompt sections are re-rendered every step and compaction keeps the system head.
- Deferred: automatic cross-requirement worktree parallelism and the architecture map, for the reasons recorded in the design.
