# Project 管家重设计 · 实机验收清单

对应设计：[Project 重设计：好用的项目管家](../superpowers/specs/2026-10-15-project-steward-redesign.md)（4.2）。分支：`project-steward-p1`。

自动化测试已覆盖逻辑与流程（见 [功能资料](projects.md)），但以下内容只能在真实桌面应用 + 真实模型中确认：**界面观感、模型是否按提示词行事、真实仓库与真实依赖下的表现**。全程约 30–40 分钟。

## 准备

- [ ] 从 `project-steward-p1` 分支按现有方式启动桌面应用（源码 `npm start` 或打包安装），使用已配置模型的 profile。
- [ ] 准备一个**小型 Git 测试仓库**（几个源文件 + 能运行的测试命令），先提交干净；再故意留一个未提交的修改（例如改 `README.md`），用于检查"不会混入原有改动"。
- [ ] 另准备一个**非 Git 目录**（第 12 项用）。
- [ ] 出问题时请记录：截图、所在步骤、当时说的话、卡片状态文字；如有报错，展开"错误详情"一并截图。

## 一、看板与提需求（P1）

1. **建项目**：添加 Project → 选择测试仓库。
   - 预期：不跑模型、不新建分支；打开的是这个项目唯一的协调者对话。
2. **闲聊不建卡**：问 3 个问题（如"这个仓库是做什么的？"）。
   - 预期：协调者正常回答；“需求”面板**没有**新卡片。
3. **明确目标直接成卡**：说一个明确的开发目标（如"给 add 函数加参数校验并补测试"）。
   - 预期：协调者用一句话告知"已记为需求"且可撤销，**不先追问确认**；“需求”面板出现卡片，状态徽标为蓝色"进行中"。
4. **模糊意图先确认**：说一句模糊的话（如"登录那块是不是有点问题"）。
   - 预期：协调者先问你是想调查还是要修改，而不是直接立卡。
5. **全局概况与状态**：“需求”面板顶部四格概况（进行中 / 受阻 / 待开始 / 已交付）。
   - 预期：数字与实际一致；数字为 0 的格子颜色变浅；卡片状态是人话（进行中、排队中 · 第 N 位、受阻、已交付…）。
6. **撤销卡片**：再提一个目标让它排队，在卡片上点"撤销"。
   - 预期：卡片进入"已取消"（“需求”面板右上 ⋯ 菜单里能看到），可重新加入队列。

## 二、项目规则（P1）

7. **规则页**：项目概览 → 资料 → "项目规则"页签。
   - 预期：说明卡片、四个常用规则开关（点一下加入、再点移除）、示例占位文字、用量条；"偏好"是另一个页签。
8. **规则生效**：写入"新增函数必须有单元测试"并保存，然后提一个新增函数的需求。
   - 预期：交付中包含测试；在成员过程记录里能看到规则出现在任务说明中。
9. **规则破例**：对协调者说"这次不用写测试"。
   - 预期：协调者确认一次后执行，并在回复中说明这是破例；交付后决策日志里有记录（第 14 项查看）。
10. **规则超限**：粘贴超过 16 KB 的文本。
    - 预期：用量条变红并提示，"保存"不可点；文本仍保留在编辑器中。

## 三、交付与改动（P2 / P3）

11. **交付卡片**：等第 3 项的需求交付后展开卡片。
    - 预期：显示"交付文件"（点文件名可在应用内打开）、"N 个文件 +x −y"、"查看改动"；协调者发布过结果页时有"查看结果页"。
12. **需求自身的改动**：点"查看改动"。
    - 预期：分文件着色 diff，前 3 个文件展开；**不包含**准备阶段留下的那个 `README.md` 修改。在非 Git 目录重复一次：显示的是目录改动说明，没有"撤销改动"按钮。
13. **撤销与冲突**：
    - a. 在已交付需求上点"撤销改动" → 确认 → 预期：相关文件恢复到开发前，`README.md` 的原有修改仍在，`git status` 中索引没被动过；卡片变为"已撤销改动"。
    - b. 另做一个需求交付后，**手动改一下它改过的某个文件**，再点"撤销改动" → 预期：弹出"无法自动撤销"并显示冲突文件，**文件未被修改**；点"交给协调者处理" → 对话里出现一条请求消息，协调者只还原该需求的改动。
14. **决策日志**：资料 → 笔记 → 展开"决策日志"。
    - 预期：每次交付一条（日期 · 需求名 · 结果 · 决策），撤销也有记录；没有出现 `<!-- decision:... -->` 这类内部标记。

## 四、连续需求与长对话（P4 / 整体）

15. **提前调查**：A 开发中时提出并授权 B。
    - 预期：B 显示"排队中 · 第 1 位"，提示"正在提前调查；前一项交付后开始开发"；B 只读不写；A 交付后 B 自动开始，**无需你再发消息**。
16. **捋一下进度**：说"给我捋一下进度"。
    - 预期：一段人话汇总，与看板一致。
17. **长对话**：在对话中手动触发上下文压缩（或积累较长对话）后，问"项目规则有哪些""之前为什么那样实现 X"。
    - 预期：回答与规则页、决策日志一致。
18. **停止与恢复**：进行中时停止，然后重启应用。
    - 预期：卡片显示已停止；重启后不自动运行模型；发"继续"后恢复。

## 五、观感（截图对比即可）

19. 浅色、深色主题各看一遍：“需求”面板（概况条、各状态卡片、下一步提示）、diff 视图、项目规则页。
    - 预期：配色与应用其他部分一致，没有"另一套产品"的感觉；文字不重叠、不截断关键信息。
20. 把窗口缩窄（约 960 × 680）重复看一遍。
    - 预期：面板内容可滚动；按钮不被挤出、不换成多行；操作反馈以浮层出现，不挤动布局。
