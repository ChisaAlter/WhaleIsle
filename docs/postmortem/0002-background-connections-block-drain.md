# Postmortem 0002: 后台长连接卡住更新、关闭和设置开关重启

## Executive summary

0.3.10 的应用内更新（整包与增量）一直失败，「关闭桌面端」失效，关闭主窗口要等约 30 秒才退出，打开 Project 开关会弹「重启将中断仍在运行的工作：2 个在途请求」，点关闭或「仍然重启」都像没反应，重开后 Project 消失。用户没做任何操作也会遇到。

这些都是同一个缺陷：更新、关闭、重启前，任务保护会锁定接纳并排空在途请求（drain，上限 30 秒）。0.3.10 新增的浮动面板（dsh-pad）在窗口打开期间一直保持 `GET /api/dsh-pad.stream` 长连接，它被算作在途请求，永远不会结束。于是：

| 现象 | 实际经过 |
| --- | --- |
| 更新下载完成后报「更新前未能安全结束正在运行的工作」 | 下载成功，安装前的 drain 超时，安装被取消（`dshd/drain-timeout`） |
| 「关闭桌面端」失效 | stop 的 drain 超时 |
| 关闭主窗口卡约 30 秒 | quit 的 drain 超时后才强制结束 |
| 打开 Project 弹二次确认 | 首次检查把长连接当活动工作，开关触发的重启要求确认 |
| 点 ✕/取消 无效 | 重启被取消，开关被写回原值 |
| 点「仍然重启」无效 | 开关转圈 30 秒，drain 超时，重启被拒，开关被写回原值 |
| 关上再打开 Project 没了 | 上面两种都把 `projectEnabled` 写回关闭 |

0.3.9 已有同类但间歇的问题：回复结束后的「下一句提示」`POST /api/conversation.next-prompt` 最长约 30 秒，正好撞上 drain 上限。

## Timeline

- 0.3.9：下一句提示进入 drain 集合，更新与关闭桌面端间歇失败。
- 0.3.10（#247）：浮动面板的 watch 流常驻，上述操作每次必失败。
- 2026-10-24：用户报告更新失败、关闭失效、Project 开关弹窗与消失。本地以 main（等同 0.3.10）复现：Project 开关弹出「2 个在途请求」；点「仍然重启」后 30 秒被拒并回写；关闭主窗口约 31 秒后进程才退出。
- 修复（#253）后同一脚本：开关不再弹窗、立即重启并保持开启；关闭主窗口 2 秒退出；drain 检查 8/8 通过，「关闭桌面端」3 秒完成。

## Root cause

drain 的本意是等「会结束、中断有损」的请求结束。实现上把所有经过 HTTP 准入的请求都放进 drain 集合，包括：

- 不会结束的请求：watch/事件流；
- 中断无损的请求：GET 读请求、下一句提示。

确认层又把「在途请求」当成需要用户同意的活动工作，所以后台连接同时造成了二次确认和 drain 超时。设置开关、插件启用/禁用本身就是用户的明确操作，却仍走需要确认的 restart 路径，取消或失败都会把开关写回原值。

## Why every test / check missed it

- 任务保护的单元测试用短请求验证 drain，没有覆盖常驻连接或长时间模型请求。
- 浮动面板 PR 只验证了面板本身，没有验证它对更新、关闭、重启的影响。
- `qa:update-download` 只验证下载，不启动应用、不安装。从下载到安装再到新版本运行的整条链路从未端到端验证。
- 设置开关的测试用桩替换重启，不经过真实的 inspect → acquire → drain。

## Guardrails added

已落地（#253）：

- `vendor/dsh-task-control/lib/wrap.js`：GET/HEAD/OPTIONS 读请求与 `/api/conversation.next-prompt` 锁内仍返回 503，但不进入 drain 集合。
- `src/main/task-control-plugin.test.js`：挂起的下一句提示、打开的 `GET /api/dsh-pad.stream` 都不阻塞 drain，且锁内新请求返回 503。
- `src/main/task-protection.js`：在途请求不触发确认，由加锁后的 drain 等待；`task-protection.test.js` 覆盖。
- `src/main/profile-ops.js` / `src/main/index.js`：内置插件开关与插件启用/禁用引起的重启带 `preConfirmed`，不弹确认；`profile-ops-toggles.test.js` 覆盖。

待补：

- Windows CI 端到端更新：安装旧版本 → 应用内整包更新与增量更新 → 确认新版本运行。需要给更新源加只在测试时生效的地址开关。
- 规则测试：打开主窗口（含浮动面板）后，更新、关闭桌面端、退出、设置开关重启都能在数秒内完成，不出现确认。

## Lessons

- 0.3.10 用户无法通过应用内更新升级到 0.3.11，因为执行 drain 的是旧代码。0.3.11 发布说明须写明：从托盘退出后手动运行安装包；或在启动器「插件排查」禁用 `dsh-pad` 后重启再在线更新。
- 新增常驻连接的功能，要验证更新、关闭、重启这些需要排空的操作，而不只是功能本身。
- 「下载成功」不等于「更新成功」；发布验证要覆盖到新版本真正运行。
- 用户点击的开关和按钮就是同意；同一操作再确认一次只会制造「点了没反应」。
