# 模块：托盘、关闭与更新

## 职责与非目标

**职责：** 托盘菜单、关闭进托盘、GitHub / CNB 发行版更新检查与安装；从托盘再打开启动器。  
**非目标：** 不实现旁路更新通道；不绕过单实例。

## 用户路径

1. 点关闭 → 按 `closeToTray` 配置进托盘或退出；首次隐藏附一次性系统 toast（指明设置入口，写 userData marker），关窗路径无任何弹窗。  
2. 托盘：显示主窗、**打开启动器**、设置、插件市场、重启 Harness、退出。文件菜单同样有「打开启动器」。  
   点击一次「退出」即进入关闭流程，不再追加工作清单或故障恢复确认。正常流程保留任务检查、接纳锁、排空和资源关停，上限 30 秒；失败时记录诊断，附加资源清理最多等待五秒后结束桌面进程。后台清理完成后先通过 Electron 正常关闭窗口；若关闭被拦截或窗口未响应，五秒后自动结束桌面进程，无需再次点击。整个退出期间的重复点击合并为同一次操作，不重启清理或延后截止时间。
   正常退出不显示、还原或聚焦主窗口；关闭遮罩只绘制在已经可见且未最小化的页面上。退出前保留当前 Harness 视图，随窗口关闭清理，不短暂切回启动页。
3. 桌面安装包的更新由**更新中心**统一负责（[update-center](../../features/update-center.md)，`src/main/update-center/`）：启动约 1 分钟后检查一次，之后每 6 小时检查；发现新版本且开启「有新版本时在后台自动下载」（默认开）时在后台下载并校验，完成后托盘菜单变为「安装 vX 并重启…」、设置角标显示「安装并重启」，并发一次系统通知。冷启动不再等待或询问更新。轻量启动器包仍使用原有冷启动询问。
4. 启动器首页提示、启动器「版本」页（检查更新、安装指定版本）、桌面「设置 → 关于」、托盘和侧栏 `dshDesktop.updates` 都打开同一个更新中心浮层并操作同一个任务：当前 / 最新版本、双语说明（「中文 / English」标签）、实际要下载的大小、进度、速度、剩余时间、续传位置、暂停 / 继续 / 取消、下载线路和自动下载开关，出错时给出原因及「重试 / 改用另一线路 / 完整下载」。
5. 更新方式由更新中心决定，界面不出现「增量」选项：Windows 安装版能取得与当前版本一致的基底、目标版本提供 blockmap 与更新元数据时，用新旧 blockmap 计算实际下载量，省下至少 20% 才用增量，界面只显示「需下载 N MB」；否则下载完整安装包。增量失败自动改为完整下载。完整下载另有不显眼的「完整下载（N MB）」入口。
6. 下载线路沿用 `downloadRoute`（GitHub / CNB），在更新中心或启动器中切换。未选时按系统区域取默认（简体中文或中国大陆时区为 CNB，其余 GitHub），默认线路不可达时自动换另一线路一次；用户选定的线路不自动更换，出错时建议另一线路。切换线路会暂停当前下载并在新线路继续，已下载的字节保留，最终以整体 SHA512 判定。完整下载的 `.part` 与续传状态（总长、校验器、预期 SHA512）写在 `userData/update-center.json`，暂停、断网、退出或重启后从已落盘位置继续。`userData/updates` 只保留当前任务的安装包，其余旧安装包在启动和检查后清理。
7. 大文件下载前先获取目标 `SHA512SUMS.txt` 条目，本次下载完成后直接做本地 SHA512 校验，不再依赖第二次清单请求。清单的响应头和正文均受每次十秒预算约束，仅暂态网络错误及与整包相同的暂态 HTTP 状态最多尝试三次，退避期间可取消；404、缺少条目及字节校验失败不盲目重试。

## 架构要点

- `tray.js`、`tray-menu.js`、`close-behavior.js`、`background-notice.js`（首次隐藏 toast）、`update-center/`（服务、IPC、浮层窗口）、`update.js`（下载与校验原语）、`update-updater.js`（增量）、`menu.js`、`launcher-gate.js`

## 实现入口

- 上列 `src/main` 文件；preload `updateCenter`（`state` / `command` / `open` / `onState`）与浮层 `src/preload/update-center.js`、`src/renderer/update-center.*`；旧的 `checkUpdate` / `installUpdate` / `installRelease` 在桌面包中转交更新中心

## 不变量

- 更新资产按平台选择：Windows Setup.exe，macOS 匹配架构的 DMG；DMG 校验后由系统打开并提示拖入 Applications，当前应用保持运行，不宣称已安装。
- 桌面版本列表与指定版本安装只接受桌面版本号；同仓库的 `whalebridge-v…` 组件发布不进入桌面更新。Windows 仅选择 Setup/NSIS/installer 安装器，不把组件或便携 EXE 当成安装包。
- 差量通道只负责下载；目标版本与 SHA512 校验后和整包路径共用任务保护 commit 中的 spawn。操作系统拒绝启动会报错、释放接纳锁，不能报告 launched 或提前退出。
- 增量基底按实际运行版本、正式发布资产及 SHA512 配对；已下载但尚未安装的新版本不能替换当前基底。blockmap 必须对应同一份安装器，不能在新版本下载完成、安装尚未完成时提升为当前基底的映射。

- 关闭行为可配置且重启后保持（验收表有持久化相关条）。  
- 更新来源为项目 Releases；`/releases/latest` 忽略 draft。启动器自 0.2.7 起随 Setup 提供，当前版本与发布状态以 [构建、钉版与发版](build-release.md) 为准。
- 冷启动更新询问/下载挂在可见启动器上；下载失败（含正文断流、字节数与 content-length 不符）删除半成品并回启动器首页，不留无窗进程（`TC-LAUNCH-008`）。  
- 整包与增量均在连接/响应头 20 秒、无数据 45 秒时关闭实际请求，持续有数据的慢速传输可继续，总耗时上限两小时。整包暂态错误最多三次尝试；已取得本次 SHA512 且服务器提供总长度时，重试从已落盘字节发起单段 Range 续传，校验起点、终点、总大小及已知 ETag/Last-Modified，最终仍对整个文件做 SHA512。服务器返回全新 200 时从零覆盖，未知大小或无校验清单从零重试；取消、重试耗尽或非法范围清理半包，不跨操作盲续。下载卡显示字节、速度、重试次数；未知大小无百分比。下载目标盘检查剩余响应大小加 256 MiB 预留；完整缓存重新通过当前清单 SHA512 才复用，新文件在 `.part` 中校验后才转正。完整收到但在本地校验或转正前取消/失败的文件可留在 `.part`，下次显式操作先取新清单并从头校验，不能直接安装。明确 SHA512 不符删除对应损坏文件；增量 pending 损坏也失效该文件，下次重新重建，旧安装器基底不动。
- 更新网络请求跟随系统代理（与 Chromium 同一判定，`src/main/system-proxy.js`）：整包下载经 HTTP 代理 CONNECT 隧道，版本查询与校验清单走 Electron `net.fetch`，增量本就走 Electron net。代理不可达或拒绝隧道时，整包下一次尝试与元数据请求改走直连；SOCKS/HTTPS 代理与直连规则保持直连。源码测试与工具在 Electron 外运行时始终直连。
- 安装包内的运行时 `deepseek-harness.tar` 由 `scripts/runtime-archive.js` 生成：第三方依赖（`node_modules`）在前、工作区包在后，文件时间由内容哈希决定。内容不变的条目跨版本字节一致，增量只需下载变化部分；0.3.10→0.3.11 的运行时实测从 91.5 MiB 降到 20.6 MiB。Electron 升级会使主程序与 Chromium 资源整体变化，此时增量仍接近整包。
- 增量操作各自持有 updater 实例；取消或超时会关闭本次实际网络请求并等待下载清理，下一次不会加入前一次的检查/下载。Electron 请求端 `close` 不代表响应结束，Range 请求保持跟踪至响应结束或错误。更新日志只增加白名单内的线路、下载方式、失败阶段和错误码，不写资产 URL、凭据或自由诊断文本。
- 安装器启动失败保留当前界面并报错；等待文案要求完成安装向导与系统授权。注册表变化不能覆盖已知安装失败；同版本父进程结束只返回待确认，收起活动进度，不能宣告完成。其余等待八分钟封顶，用户也可停止等待。
- Windows 安装登记中的路径与版本通过 Unicode 注册表接口读取，中文及 emoji 目录不受命令行输出编码影响；读取和检测不修改已有安装登记。
- 桌面内置启动器的版本状态对应当前运行版本，注册安装版本与位置单独标示；运行未安装的目录包不等于覆盖已有安装。独立启动器仍显示其管理的桌面安装版本。
- 启动器归属的确认（更新询问、无校验清单安装）经 `launcher/launcher-confirm.js` 桥渲染成启动器 `app-confirm` 窗内卡；桥不可达才回退原生框。安装/更新/停止链 `preConfirmed`——入口动作即同意，任务保护不再二次确认；显式 quit 同样不再确认，restart/reload 保留活动任务确认。
- 桌面在跑时关启动器 ≠ `app.quit()`；桌面未启动时关启动器 = 退出应用。

## 门槛

- QA：`TC-LAUNCH-006`、`TC-DESK-002`（托盘须含「打开启动器」）。`npm run qa:update-download` 使用真实 Electron 网络栈与本地 Range 服务，验证停滞清单/Range 的取消、超时、错误响应清理和显式重试；只用独立临时缓存，不打开应用窗口或运行安装器。
